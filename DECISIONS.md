# DECISIONS.md — product decisions and reasoning

**Brainstorm-only.** Load this when exploring product direction, questioning a design choice, or proposing a change that might undo one. Not needed for routine code/UI edits (CLAUDE.md has the rules; this has the *why*). Each entry: decision → why → rejected → revisit when. Add new entries at the end of its section; don't rewrite history, mark `SUPERSEDED by Dn`.

## A. Product

**D1 Sell traceability, not intelligence.** Why: a chatbot answers in seconds but may invent, can't be checked, and isn't reproducible. Value = sources, rejected candidates, stated limits. Rejected: "smarter model" positioning (commodity, unverifiable). Revisit: if users ask for scoring/ranking more than for proof.

**D2 Identity before research; ambiguity is a hard stop.** Why: same-name companies produced polished reports about the wrong firm (Sprout Design → UK studio). An earlier "is this who you meant?" confirm was unsafe (a "no entity verified" description still got a yes and wasted the budget). A URL is unambiguous and outranks search. Rejected: confirm-and-continue. Revisit: only with a stronger entity-resolution source.

**D3 Verification is a separate call, with the target's scale.** Why: a model re-checking its own reasoning agrees with itself. But passing only the *name* made "comparable in scale?" unanswerable (80-person agencies passed as peers of a 2-person studio). Independence = withhold reasoning, never the subject. Rejected: same-chat verification; name-only verifier.

**D4 Sources tracked in code, citations validated against it.** Why: models fabricate plausible URLs (real case: `…mvp-design-agencies…` vs the fetched `…mvp-agencies…`). Detection alone isn't enough — a broken link still looks like evidence — so fabricated citations are stripped. Rejected: trusting model attribution; flag-only.

**D5 Label corroboration by distinct domain; don't reject single-source.** Why: two pages on one site aren't independent. A small real company may legitimately have only its own site. So: label (corroborated N / single-source / none), never reject on it, never present with more confidence than evidence. Rejected: min-sources gate (would drop real small companies).

**D6 Mandatory human review; show rejections.** Why: automated checks miss things; auditability of judgment matters more than a clean list. Report lists every rejected candidate with reason, automated and human. Rejected: auto-publish; showing only kept results.

**D7 Listicles labeled at the source; research can verify past them.** Why: "best X agencies" content dominates results and a real competitor's own blog can host both its site and a self-ranking roundup, so domain blocking fails. Tag by URL pattern; give research an `extract_company_page` tool; track `primary_source_ratio`. Limit: mitigation, not a fix.

**D8 Retry selectively.** Why: 429/5xx/transport drops are transient; a 404 (retired model) fails forever and burns quota. Retries cover tool calls too (found via a live `RemoteProtocolError`).

**D9 Gates vs observations in evals.** Why: live search varies by day; asserting on it tests this morning's index, and a flaky test trains people to ignore real failures. Gates = never-break invariants; observations = reported, never failing. Each regression case = a bug that actually happened.

**D10 No agent framework.** Why: learning the mechanics (tool loop, structured output, verification) was a goal. Revisit: if maintenance cost outweighs that.

**D11 One shared API key for the public demo.** Consequence: free-tier exhaustion is an expected state, not an edge case; UI handles 429 plainly (P6). Revisit: per-user keys or caching if usage grows.

## B. Platform / structure

**D12 Pipeline is UI-agnostic; only `moat_app.py` imports Streamlit.** Why: CLI and web share one code path; keys come from env, `.env`, or `st.secrets` bridged before import. Rejected: UI logic in pipeline.

**D13 Dual deployment (Docker/Render + Streamlit Cloud).** Why: demonstrates packaging for a container host and a platform host. Docker gotchas: bind `0.0.0.0`, honor `$PORT`, `exec` for PID 1, `.dockerignore` excludes `.env`.

## C. Design system (decided 2026-10, UI work)

**D14 Import Ant Design as tokens, reference-only.** Why: user wanted a full, official system (variables, tokens, components, spacing). Ant's components are React; this app is Streamlit, so tokens are the portable part. Extracted programmatically from `antd` (not hand-copied) so it regenerates on upgrade. Not wired into the UI yet (no visual change). Rejected: rewriting in React (out of scope); hand-copying values (drifts).

**D15 Spacing: 4px unit, 8px grid by convention.** Why: Ant's `sizeUnit` is 4px; the user's standard is an 8px grid. Even steps are the default, odd steps (4, 12) are half-steps inside one component only. Dropped Ant's 20px "MD" and a 28px step as off-grid. Step names follow Tailwind (`space-4` = 16px) so they're guessable. Semantic aliases (`--stack-*`, `--inset-*`) are what components use, so a spacing change edits one alias, not every call site. Rejected: raw 4px freedom (inconsistent), exposing every Ant step (noise).

**D16 DESIGN.md is a rulebook with IDs; CLAUDE.md is a router.** Why: token cost. CLAUDE.md loads every session, so it stays short and points to files; DESIGN.md has a ≤15-line quick card for small edits and numbered rules to cite; this file holds reasoning and loads only when brainstorming. Don't duplicate values across files; reference variable names.

**D17 Honesty rules are design rules (P1–P8).** Why: the product's value is calibrated trust; a UI that looks more certain than the data (green everywhere, hidden single-source labels, collapsed rejections) breaks D1/D5/D6 even if the pipeline is right.

**D18 Light mode only (for now).** Why: user decision to ship one theme first. It also removes Streamlit's default of following the OS, which rendered dark on dark-mode machines with nothing designed or contrast-checked. `config.toml` pins `base = "light"`; dark tokens stay in `design-system/` so re-enabling is a build change, not a rewrite. Rejected: following the OS (untested second theme).

**D19 Apply the system via a generated theme + one stylesheet; fix Ant where it fails AA.** Why: Streamlit's native theme options cover color/font/radius/headings, so most of the sync lives in a generated `config.toml`; CSS only does what the theme can't. Ant defaults that fail WCAG AA were replaced with the nearest passing Ant palette step, not invented colors: primary `#1677ff` -> `#0958d9` (white label 4.1:1 -> 6.2:1), widget border `#d9d9d9` -> `#8c8c8c` (1.4:1 -> 3.4:1, needed to identify inputs), status hues to the 7th/8th step, captions' 60% opacity -> secondary text. Cards keep Ant's quiet `#f0f0f0` border. Rejected: shipping Ant defaults verbatim (fails the AA rule we set); hand-picking colors (drifts from the system). Revisit: if brand blue must stay `#1677ff`, use it only for large/bold text.

**D20 "Research" is the primary action.** Why: DESIGN section 7 allows one primary per view and the form had none styled. `type="primary"` is the only `moat_app.py` behavior-neutral change besides loading the stylesheet.

## D. Accounts, landing and legal (decided 2026-10-26)

**D21 Streamlit multipage, not Next.js.** Landing, tool, account and legal pages are `st.navigation` pages with a hidden sidebar and our own header. Why: one deploy, reuses the Ant theme, no rewrite of a working tool. Cost: landing layout is limited to Streamlit + our CSS. Rejected: Next.js + FastAPI (two deploys, tool would need embedding/rewrite). Revisit: if marketing needs outgrow this.

**D22 Google sign-in only, via Streamlit's native OIDC.** Why: no passwords to store or leak, no reset flow, no email service. Identity = Google's stable `sub`; the email must be verified by Google; scopes are only `openid email profile`. A `CRA_DEV_AUTH=1` bypass exists for local work and is off by default. Rejected: email+password (we'd own breach risk), magic link (needs an email provider), Supabase Auth (vendor lock-in for two tables).

**D23 Database: SQLite locally, Postgres in production, one `DATABASE_URL`.** Why: 100-200 sign-ups/month is tiny, but free hosts wipe local disks on redeploy, so production needs a real DB (a free Postgres such as Neon fits in a fraction of its limit). Stores users + daily usage only. Searches and reports are not stored (smaller privacy surface; revisit when "past reports" is built, then update the Privacy Policy). `create_all` instead of migrations until the schema first changes.

**D24 Usage limits: 3 runs/user/day, 150/day overall, reserved before the pipeline, never refunded, reset 00:00 UTC.** Why: one shared Gemini/Tavily key (D11). Reserving first stops parallel tabs overspending; no refund keeps it simple (failed runs still cost quota). The global cap is a soft read-then-write limit. Values are env-tunable.

**D25 Legal pages are versioned Markdown with placeholders; consent is explicit and recorded.** Terms + Privacy live in `legal/*.md`, filled from `OPERATOR_NAME` / `CONTACT_EMAIL` / `JURISDICTION`; a visible draft warning shows until those are set. Two required, unchecked boxes (agree + 18+) after sign-in; we store which version and when. Bumping `LEGAL_VERSION` forces re-consent. Account deletion is in-app and hard-deletes. The text is a draft for a lawyer to review, not legal advice.

**D26 Legal operator and jurisdiction (2026-10-26).** Operator is an individual, Sravya Dangeti, until a company exists; contact is her email; governing law is India, audience mainly India/Asia. So the Privacy Policy leans on India's DPDP Act 2023 (adds the right to nominate someone, grievance route to us first, then the Data Protection Board) and does not add GDPR-specific machinery. A personal name on public legal pages is a real exposure: she is the legally responsible party and the grievance contact, so she must agree to it. When a company is registered, change `OPERATOR_NAME` and bump `LEGAL_VERSION`. Brand name is separate and still TBD (shortlist: Sourcewise, Cairn, Assay, Pramana). Not yet set: which city's courts the Terms name; a lawyer should add it.

**D27 Landing concept: an editorial ledger, not a SaaS template (2026-10-26).** Reference was hazel.ai (warm gradient bands, big editorial headings, product-mock hero, bento, giant footer wordmark). Kept its structure, replaced its look with our system: display serif on warm paper, ink-blue bands with an amber glow, all derived from Ant palette tokens. Signature device: the page cites itself (footnote numerals, a margin note on the mock, ruled lines). Each section has its own composition (ledger rows, sticky timeline, scroller, mixed-surface bento, comparison table) instead of repeated icon cards. All sample data is real (from `example-report.md`), and Hazel's logos, testimonials and stats were not imitated (P7). Context saved in `.impeccable.md`.

**D28 Motion: GSAP vendored, JS via `st.html(unsafe_allow_javascript=True)`.** Streamlit has no first-class way to run page JS, but this API plus static serving works. GSAP and plugins are vendored (no CDN: keeps visitor IPs private and the Privacy Policy true). Motion is gated by `prefers-reduced-motion`, uses transform/opacity only, reveals once, and the hero entrance is plain CSS so there is no flash. Lag smoothing is off so entrances finish after a stalled frame. Rejected: count-up on 6/2/1 (no meaning), animating the FAQ, hero parallax (decorative, no purpose), Lottie/video hero (weight).

**D29 Landing pitfalls found the hard way** (so nobody rediscovers them): Streamlit's sanitizer strips inline `<svg>` and drops an entire `<style>` that contains `<`; Streamlit scrolls `stMain`, not the window; `st.table` pulls in pandas/pyarrow (avoid); a plain `<a href>` is the right navigation primitive for CTAs.

**D30 Hosting: everything on Vercel, Streamlit as an ASGI app (2026-10-27).** Owner asked for site and tool both on Vercel at sravya-cra.vercel.app. Vercel has no long-running server, but `streamlit.App` (ASGI) + Vercel's Python runtime + WebSockets works; verified locally under uvicorn first, then in production. Entry is `index.py` (`[tool.vercel] entrypoint` in `pyproject.toml`), `vercel.json` sets `maxDuration` 300. Cost of this choice: a WebSocket closes at max duration, Streamlit reconnects with a NEW session, so in-progress state (a half-done review, an unsent report) is lost; accounts and quotas survive because they are in the database. The filesystem is read-only, so local SQLite falls back to `/tmp` (ephemeral): **production needs `DATABASE_URL`**. Google sign-in secrets come from env vars (`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `AUTH_COOKIE_SECRET`, `SITE_URL`) via `index.py`, because there is no `secrets.toml` on Vercel. Rejected: Render/Streamlit Cloud (works better for sessions; kept as the fallback if session loss hurts), rewriting the tool in Next.js (the right long-term shape for Vercel, but a rewrite).

**D31 Landing redesign: plain proof (2026-10-28). SUPERSEDES D27.** Owner found the ledger version naive and "Claudey". Rebuilt from five measured references (DESIGN.md section 15 has the table): near-monochrome, one self-hosted grotesk (Instrument Sans, 30 KB variable woff2, OFL) at weight 500 with tight tracking, a near-black CTA, no borders (grouping by space and one quiet surface), two licensed Unsplash photos (card catalog, annotated desk; owner approved the downloads) with real product fragments floating on them, the pipeline as a numbered flow of real fragments with connectors that draw in, one 17-icon mask family (`design-system/gen-icons.js`). Copy cut by about half. Still honest: every number and name on the page comes from `example-report.md` (36 pages, 24 sites, the five competitors, Airtable's unverified price). Rejected: keeping the serif (it was the main "AI editorial" tell), people photos (we have no customers to show), a stats strip, the giant footer wordmark.
